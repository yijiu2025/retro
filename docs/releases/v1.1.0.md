## ⚠️ 先看这条：升级后必须做的两件事

**1. 改了 `web/model_runtime.py` 或 `web/model_server.py` 之后，必须重启模型服务。**

模型跑在独立常驻进程里，API 进程不加载模型。这正是「重启 API 不用重载 9GB 权重」
的代价 —— 两边都要各自重启。

**2. 用了 Docker / 跨主机部署的话，检查 `RETRO_MODEL_HOST`。**

这个变量是本次新增的。默认 `127.0.0.1`（同机双进程，**不设也能跑**），
但**容器里必须改成服务名**，例如 compose 里的 `model`：

```yaml
environment:
  RETRO_MODEL_HOST: model      # 不是 127.0.0.1！
```

原因是两个容器是**独立的网络命名空间** —— 在 api 容器里 `127.0.0.1` 指向它自己。
不改的症状很隐蔽：只表现为「模型一直 loading」，看不出是地址问题。

## 🐛 修复

### 异步搜索静默丢掉搜索算法（最严重）

`/api/jobs` 收下了 `algorithm` 参数，但 `jobhub` 的 runner 是照着同步接口字段
**逐个挑**转发给搜索桥的，漏挑了它。

⇒ **选 BFS 会静默拿到 Retro\* 的结果，不报错、无任何提示。**

同时修掉了进度栏里硬编码的「Retro\* 广度优先」文案 —— 它本身也自相矛盾
（Retro\* 是最佳优先，不是广度优先），现在会随所选算法变化。

### 毒性（toxicity）分析模块形同虚设

用户勾选部分分析模块时，精简提示词路径**只拼了字段名、没拼模块描述**。

⇒ 勾「毒性与防护要点」时，模型只知道「要有个 toxicity 键」，不知道该写什么，
也不知道与「安全与放大」的区别 —— 恰好退化成一张重复的「注意防护」清单，
正是这个模块本要解决的问题。已把描述拼回提示词。全量路径行为不变。

### 正向模型没有加载进度

只有逆向模型有 `progress`，正向会返回空值，前端进度条会断。已补齐，
锚点按正向模型的实际阶段（不 spawn 规则子进程，少一段）重新划分。

## ✨ 新增：Linux / Docker / systemd 部署

原先只有 Windows 的 `.bat`，Linux 上只能手工拼命令。现在：

| 入口 | 用途 |
|---|---|
| `scripts/setup_env_linux.sh` | 从零建环境（`--venv` / `--gpu cu121`） |
| `start_api.sh` | 启动（`--check` 环境体检、`--model` 只起模型服务） |
| `Dockerfile` | 容器镜像，CPU/GPU 双模式 |
| `docker-compose.yml` | model + api 两服务编排 |
| `deploy/systemd/*.service` | 生产单元，含内存上限与安全加固 |
| `deploy/部署Linux.md` | 完整部署指南 + 8 条排障 |

### ⚠️ 别用 `pip install -r requirements.txt`

这个项目的依赖对**版本和顺序**都很挑，脚本已把顺序固化：

- PyTorch 必须用官方 wheel 源（conda 通道会拉到冲突的构建）
- numpy 必须锁 1.x（torch 2.2.2 是按 numpy 1.x 编译的）
- PyG 家族的 wheel 目录名是 `torch-2.2.0`，**不是** `2.2.2`（上游笔误）

### Docker 的几个要点

- **权重不要打进镜像**。`models/` 的 9GB 已在 `.dockerignore` 里排除，必须用 volume 挂载。
- **model 服务不映射端口**。它没有任何鉴权，能连上就能吃满整台机器。
- 健康检查 `start_period` 给到 240 秒 —— 首次加载约 2 分钟，否则会被判定失败而反复重启。

## 🔧 其它

**`.gitattributes`**（新）— 强制 shell 脚本为 LF。

这条**很容易踩坑且本地发现不了**：Windows 上 Git 检出时会把 LF 转成 CRLF，
于是 `#!/usr/bin/env bash` 末尾多一个 `\r`，Linux 内核解析 shebang 时会
把它留在解释器路径里，直接报：

```
bad interpreter: /usr/bin/env^M: No such file or directory
```

而本地 Windows + Git Bash 往往能正常跑（对结尾 `\r` 宽容），
只有真正部署到 Linux 时才暴露。
